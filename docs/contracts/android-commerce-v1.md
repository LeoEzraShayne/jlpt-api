# Android commerce V1 — frozen 2026-09-13

This main-agent contract freezes the route table and behavioral requirements in [A0 proposal](android-a0-commerce-proposal.md), with the mandatory corrections below from [independent review](android-a0-independent-review.md). It is an implementation contract, **not a claim of live Android payments, ads, or completed device acceptance**. Shared schema/env and TypeScript wire types accompany this document. Android code and endpoints remain disabled for release until their platform and device gates pass.

## Identity, binding and browser entry

- Production package `com.meritledger.app`, development package `com.meritledger.app.debug`. No debug certificate is added to production Digital Asset Links. A debug package is not evidence of a real Play purchase for the production package; internal Play testing must use the actual package/signing identity and an isolated test backend/database.
- Release/test client IDs are `android-release` / `android-test`. Fixed callbacks are `/android/callback` / `/android/callback/test` on configured FRONTEND_URL. A live backend accepts only release, an isolated test backend only test. There is no arbitrary redirect URI.
- Binding start URL is `/android/link?bindingId=<UUID>`. Add **GET `/api/v1/android/auth/bindings/:id`**, guarded by Web SessionGuard, returning `AndroidBindingDetails` for the approval page. Other routes/DTOs remain the proposal's exact table. Exchange additionally returns the bound account email so native purchase screens clearly identify the recipient.
- Request lifetime 10 minutes; authorization code lifetime at most 60 seconds and never beyond the request expiry; bearer lifetime at most 60 minutes and never beyond its source AuthSession. Source session must exist, remain unexpired, and belong to the same user on **every** native request. Replacing a Web login cookie invalidates its previous source session/native bindings, including account switching; logout does likewise. Preserve other devices' unrelated Web sessions. Exchange is one-shot and requires S256 verifier and matching client ID; native independently verifies its callback state.
- Native commerce navigation is a user-clicked, fixed package-targeted intent: `intent://commerce?action=membership#Intent;scheme=jlpt;package=com.meritledger.app;end` or action `reward`. Debug uses only the fixed `.debug` package. It carries no token, user ID, price, or return URL and conveys no authority; native strictly validates scheme/host/action and independently checks its session and server status.
- TWA startup adds `platform=android&client=android-release` (debug `android-test`) to `/today`. This tab-scoped UI hint only hides Stripe and exposes the fixed native navigation. It never authenticates an account or grants benefits. Capture it before protected-route/login redirects; retain only safe same-site continuation paths. Ordinary Web tabs continue using Stripe. Do not rely on User-Agent or package text as proof of identity.
- Binding callback responses use no-store/no-referrer and minimal content without third-party assets; do not display codes, include bearer in the URL, or forward them to analytics. OriginGuard exemptions are **exact native POST routes only** (binding start/exchange/logout, purchase verify, reward creation and OIDC RTDN); binding approval remains cookie+Origin protected. Exempting Origin does not replace the route's actual authentication/signature guard.

## Durable state and Google verification

The actual migration is authoritative: five new tables, nullable `User.googlePlayAccountId`, nonunique many-to-one `BillingEvent.googlePurchaseId`, and independent default-false `BillingConfig.androidSalesEnabled/androidRewardsEnabled`. Existing Stripe flags, orders and timestamps remain unchanged.

- GooglePlayPurchase is the durable token queue. userId/productId can be null until Google proves ownership; persist encrypted token before acknowledging RTDN, then reconcile under AWAITING_OWNER/retry state as needed. Many event IDs can refer to the same queue row. No fabricated user and no raw purchase token in BillingEvent/payload/logs.
- Queue revision increments for new work. Claim a random leaseToken with leaseUntil; every stale-sensitive write compares both fence and observed revision. A notification arriving during verification must leave work scheduled, not be lost by an older worker. Consumption is attempted only after committed grant/order and is retried durably. Commit failure must not consume. A stale successful result cannot resurrect a refunded grant.
- Preserve Google's lastEventTime as its full RFC3339 string (including submillisecond precision); it is not an invented opaque revision. Use trusted Orders Money for original totals and successfully processed refund totals, exact integer currency conversion, and monotonic refundedAmount. Do not count pending refunds or derive refunds from developer revenue. A full REFUNDED terminal record is a tombstone even if it arrived before owner/grant mapping.
- AndroidCommerceSyncState stores the voided-purchase watermark and fenced lease. Advance only after every page in the overlapping interval succeeds; retain failure state, respect Google's 30-day historical limit, and report a gap beyond that window. RTDN is an authenticated hint and must be revalidated against Google.
- Test and live run on isolated databases. Refuse Android test commerce in the production `jlpt` database, even if deployment flags are accidentally set. testPurchaseContext must match the configured environment, never a client field. SDK test ads/console test callbacks never increase production balances.
- Purchase token encryption uses a separate protected 32-byte key with a versioned AEAD envelope; do not rotate/remove the key without retaining decryptability of existing tokens. No Google credential is embedded in Android/Web or committed.

## Products, launch and rollout flags

Two one-time products `jlpt_day_pass` and `jlpt_year_pass`, purchase option `buy`, annual offer `launch-64`. Native must precisely select these details/offerToken and use Google's localized formatted price. No silent fallback from a missing launch offer to $99. The immutable shared deadline is **2026-12-11T23:58:15.676Z**; the original launch is **2026-09-12T23:58:15.676Z**. Google requires whole-minute offer expiry, so its offer ends at **2026-12-11T23:58:00Z**. Only the native catalog omits YEAR_PASS during the intervening 15.676 seconds; DAY_PASS stays available. At the shared deadline the native catalog returns the standard annual purchase option. Web pricing and the shared launch clock retain their exact timestamps. A late confirmed purchase receives its valid purchased entitlement; notification delay does not justify withholding paid service.

`ANDROID_COMMERCE_ENABLED` gates native endpoints. `ANDROID_GOOGLE_ENABLED` plus `androidSalesEnabled` gates new native purchases. `ANDROID_ADMOB_ENABLED` plus `androidRewardsEnabled` gates new reward tickets. Native entitlements expose the native reward flag; Web `rewardsEnabled` stays false. Google cancellation/refund reconciliation and valid already-earned SSV rewards must not be lost solely because new sales/ads are disabled.

## Reward tickets and SSV

- No single-active-ticket restriction. requestKey is idempotent, creation is rate-limited, secret hashes only are persisted. Lost-response retry on the same key returns TICKET_RESTART_REQUIRED; the client may use a new key. Older genuinely earned tickets remain redeemable.
- Each ticket stores the full SDK adUnitId **and** numeric ssvAdUnitId, opaque per-ticket ssvUserId, rewardItem `jlpt_task`, and a random base64url customData hash. Reward is exactly one task. The ticket's earned-time window is 20 minutes plus a fixed 60-second clock skew; an expired UI status cannot reject a later delivered callback whose signed earned timestamp is inside that window. Timestamp is **milliseconds**.
- Verify signature before trusting fields, preserving parameter order without object reserialization or double/form decoding. Determine exact signed bytes against Google's official verifier and callback vectors, including percent encodings/UTF8 and duplicate-key ambiguity; do not assume raw URL bytes equal Java URI.getQuery(). Strictly reject ambiguous duplicate fields.
- A ticket and transaction can each be redeemed once, under the user's billing lock. Match owner alias, customData hash, numeric unit, item and amount. A member does not start an ad, but purchasing membership after an already earned reward does not erase it. Client SDK callbacks only trigger status refresh.
