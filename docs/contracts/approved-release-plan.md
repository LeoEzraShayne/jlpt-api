# JLPT Sentence Lab 多子 Agent 开发与发布计划

## 一、目标与已确定业务

采用 **一个主 Agent＋七类子 Agent，同一时间最多三个子 Agent 工作**。分两阶段交付：

1. **Web 阶段**：完整中英文体验、Stripe、会员与额度后台，部署并开放收费。
2. **安卓阶段**：复用 Web，完成安卓工程、Google 支付、AdMob、商店素材和正式发布。

### 商品与权益

| 项目 | 已确定规则 |

| 免费版 | 语法新学、复习及词汇练习合计每天 5 个任务 |
| 免费任务 | 每个任务包含首次批改及两次修改，共 3 次成功批改 |
| 广告奖励 | 完成一次激励广告增加 1 个任务，未使用奖励保留 |
| 日票 | $0.99／¥100，付款成功后连续 24 小时 |
| 年卡 | 美元首发 $64、常规 $99.99；日本 ¥6,400，有效期 365 天 |
| 首发期限 | Web 正式收费起 90 天，安卓共用同一截止时间 |
| 会员 | 免广告，正常学习暂不设每日任务或批改次数上限 |
| 续购 | 一次购买、不自动续费；有效期内续购保留剩余时长 |
| 调价 | 只影响后续购买，旧订单价格与权益保留到期 |

## 二、Agent 分工与写入边界

| 角色 | 职责 | 允许修改的范围 |
|---|---|---|
| **主 Agent** | 业务契约、共享模型、迁移、集成、浏览器配置、生产部署与发布 | 数据库模型和正式迁移、公共接口类型、部署配置、平台账户 |
| **A：支付与权益** | Stripe、Google 订单校验、会员、额度、续购退款、广告奖励账本 | 后端支付、权益、额度及任务接入模块 |
| **B：Web 体验** | 会员购买页、订单页、额度提示、中英文界面、移动端反馈 | Web 页面与组件、前端交互测试 |
| **C：语言与内容** | 语法英文讲解、例句译文、词汇释义、翻译校验及术语一致性 | 内容翻译模块、语言资源、可追溯的内容导入 |
| **D：AI 与成本** | 中英文批改、完整用量记录、便宜模型评估、失败与重试成本 | AI 提供商、提示词、评分输出与成本统计模块 |
| **E：安卓工程** | TWA、原生 Google Billing、AdMob、登录衔接和安卓交互 | 独立安卓工程及安卓测试 |
| **F：独立验收** | 数据库集成、并发、支付异常、跨端、迁移和设备验证 | 独立测试与验收材料，不直接重写业务实现 |
| **G：品牌与素材** | 图标、宣传图、真实截图、中英文商店介绍、更新说明 | 发布素材与文案，不修改业务代码 |

### 协作约束

- 后端、Web 分别使用隔离 worktree；安卓使用独立仓库。禁止在同一个工作目录并发编辑。
- 主 Agent 先锁定接口和字段；子 Agent 如需修改公共模型，提交需求，由主 Agent 统一处理。
- A 拥有支付和额度逻辑；D 拥有 AI 调用与批改逻辑。两者通过明确的任务授权和用量接口衔接。
- C 负责静态内容与翻译资源；D 负责运行时 AI 输出语言；B 负责界面接入，避免同时修改相同翻译文件。
- **所有 Stripe、Google Play、AdMob 和云控制台操作仅由主 Agent 执行**，子 Agent 不接管已登录浏览器。
- 密钥、签名密码和服务账号材料保存在受保护的配置中，不进入代码、截图、文案或 Agent 交付报告。
- 每次交付包含：提交版本、变更摘要、接口影响、验证结果、迁移需求和未解决问题。
- F 发现问题后交回对应负责人修复，主 Agent 集成后再复验。

## 三、第一阶段：Web＋Stripe＋共用后台

### 执行顺序

| 批次 | 并行安排 | 主 Agent 工作 | 交付条件 |
|---|---|---|---|
| **W0：基线与契约** | 暂不派实现 Agent | 记录仓库状态，确定商品、订单、权益、额度、语言接口和迁移顺序；只读核对 Stripe 账户 | 各 Agent 获得相同业务契约 |
| **W1：基础开发** | A 支付权益；B Web 页面；C 静态中英文内容 | 统一模型与迁移，配置 Stripe 测试环境，持续集成 | 测试环境能完成购买与权益展示 |
| **W2：批改与联调** | D AI 语言和成本；B 页面联调；F 独立测试 | 集成 A/C 交付，核对订单状态与任务额度 | 完整中英文学习及付款流程通过 |
| **W3：修复与发布** | F 复验；对应模块负责人修复，最多三人 | 配置正式商品与 webhook、备份迁移、部署、授予 VIP | 正式收费可用，首发倒计时开始 |

W1 完成后再启用依赖共用接口的 W2 工作；验收测试可以提前按锁定的契约编写。

### 主要实现

**A：支付、会员与额度**

- 使用 Stripe 托管 Checkout；服务端确定有效商品和价格，订单保存成交快照。
- 通过已验证的 webhook 和支付平台状态发放权益，不凭成功页或客户端回调开通会员。
- 支持待付款、付款失败、重复通知、乱序通知、退款及争议处理。
- 日票、年卡采用一次性购买，记录独立权益来源；撤销一笔订单不影响其他有效权益。
- 免费和广告任务额度采用统一账本，支持预留、消费、释放和并发校验。
- 为词汇任务增加追加批改记录，保留首次提交作为正式记忆证据。
- 指定账号的 VIP 通过幂等赠送记录开通，不修改管理员身份或伪造订单。

**B／C／D：中英文完整体验**

- 品牌统一为 **JLPT Sentence Lab**。
- 覆盖登录、计划、今日任务、语法库、词汇库、练习、批改、历史及会员页面。
- 静态语法解释、例句译文和场景说明翻译入库；词库复用现有英文原释义，保留中文补充与来源。
- 用户选择界面和讲解语言；日语原文保持日语。学习会话保存语言，历史记录不因切换语言被改写。
- AI 批改继续突出“需要调整的地方”，不重新加入已经移除的冗余拓展卡片。
- 去除手机浏览器默认触摸高亮，保留必要的按钮反馈和键盘焦点。

### 公共接口与数据

由主 Agent 统一维护以下能力的契约：

- 商品、市场价格和首发有效期查询。
- 当前会员、到期时间、免费额度、奖励余额及订单历史。
- Stripe Checkout 创建、付款状态与 webhook。
- 任务额度预留、消费、释放及追加批改授权。
- 用户语言偏好、多语言静态内容与会话输出语言。
- 完整 AI 调用记录：模型、输入、输出、思考、缓存、重试、耗时及关联任务。

迁移采用兼容性增量修改，保留旧字段及全部学习记录；不把历史学习任务追溯计入收费额度。

### 成本验收

D 与 F 独立核对：

- 普通使用：每天约 20～40 次批改。
- 重度使用：每天约 120～240 次批改。
- 计入词汇出题、思考、重试、支付费用及服务器成本；不把共享免费额度当成永久零成本。
- 便宜模型必须通过中英文批改质量回归，才可替换默认模型。
- 核验完成前不开放真实收费。若成本无法支持已定价格与会员权益，报告结果重新商议，不擅自添加隐藏上限。

## 四、第二阶段：安卓工程＋支付广告＋上架

### 执行顺序

| 批次 | 并行安排 | 主 Agent 工作 | 交付条件 |
|---|---|---|---|
| **A0：安卓契约** | E 工程设计；A Google/广告后端接口 | 核对原应用、最高版本号、签名、旧订单与 AdMob 状态 | 应用身份及跨端接口明确 |
| **A1：并行实现** | E 原生工程；A Google/SSV 后端；G 品牌素材草稿 | 串行配置测试商品、通知和广告，集成跨端能力 | 测试版可登录、购买、看广告和返回学习 |
| **A2：实机验收** | F 实机与异常测试；E 修复；G 最终截图文案 | 验证正式签名、跨端权益、平台配置与旧版本升级 | 发布包、素材和验收结果一致 |
| **A3：提交发布** | F 上线核验，其余按问题参与 | 上传 AAB、更新商店资料、提交审核、处理反馈并发布 | 审核通过后正式版可下载安装 |

### 安卓工程

- 使用 TWA 复用 Web，原生实现 Google Play Billing 和 AdMob 激励广告。
- 正式包名沿用 `com.meritledger.app`，作为功过格更新，版本号超过控制台最高版本。
- 核对上传证书与 Google Play 应用签名证书；网站关联配置使用实际安装包对应证书。
- 测试包使用独立后缀，避免开发安装覆盖正式应用。
- 网站与原生支付广告页面使用经过验证的关联和短时账号绑定流程；客户端不能自行指定会员归属。
- 登录、状态栏、系统返回键、键盘遮挡、安全区域、断网恢复及支付后返回练习必须实机验证。
- 原生文案提供中、英、日文；网页完整支持中英文。
- 精简并修正新工程的 Android 规则，不复制旧文档中的明文签名信息或无关权限。

### Google 支付与 AdMob

- 安卓显示 Google 的商品价格和付款界面，不显示 Stripe 购买按钮。
- 后端验证 Google 购买状态、商品、应用和账号归属，发放权益后完成消费确认，允许再次购买。
- 接入实时开发者通知和退款核对；处理 pending、取消、断网、重复回调、恢复购买及应用被杀死。
- 广告奖励由后端验证 SSV，绑定账号与唯一奖励事件；重复通知不重复发奖。
- 测试阶段只使用测试广告；正式广告上线前完成适用的同意流程。
- 会员不展示广告入口，广告无法加载时不扣额度。

### 浏览器与发布素材

主 Agent 使用已登录的 Stripe **Leo Shayne Studio** 账户与 Google Play 管理中心执行配置；需要其他相关控制台时继续使用用户授权的浏览器流程。

G 交付：

- 应用图标、Google Play 宣传图。
- 真实完成界面的中英文手机截图。
- 中英文短介绍、完整介绍和更新说明。
- 商品权益及期限文案，不宣传未实现的功能或保证通过 JLPT。

主 Agent 根据实际 SDK、账号和数据流填写隐私、数据安全、广告及应用访问说明，不能仅按模板勾选。

当前 Play 控制台显示功过格为正式版、安装用户数 16。发布前核对实际订单和账号，不把安装数等同于付费人数；保留原项目与数据备份，不执行无必要删除。若发现其他真实已购权益，先保留并核清承接关系。

## 五、最终验收与交付标准

F 必须覆盖：

- 免费第 5／第 6 个任务、任务第 3／第 4 次批改、系统失败、跨天及恢复。
- 多设备、并发任务、重复完成、重复付款和重复广告通知。
- 24 小时、365 天、提前续购、会员到期、赠送 VIP 和退款。
- 首发 90 天边界、旧订单权益保留、美元与日元金额。
- Stripe 购买在安卓生效、Google 购买在 Web 生效、不同账号不能共享或抢占订单。
- 语法与词汇首次记忆证据不被追加纠错重复计入。
- 中英文内容完整、读音与译文对应、核心纠错质量和完整 AI 成本。
- 安卓原版升级、实际签名、登录跳转、支付返回、广告奖励、离线及进程重启。

每阶段完成后交付：

1. 已提交 GitHub 的配套版本。
2. 数据库迁移与回退说明。
3. 测试、实机及成本核验结果。
4. 平台商品、回调和广告配置清单，不包含秘密值。
5. 实际部署或商店提交状态，区分“已上传”“审核中”和“已正式发布”。

生产回退保留订单、权益和学习记录；出现支付或广告异常时可关闭新增购买或奖励入口，已有有效会员继续正常使用。
